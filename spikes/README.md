# Spikes

Each spike answers one question that blocks a milestone. Results are recorded here as they are run; a spike is never
marked PASS without the run that shows it. Captured output (`spikes/**/out/`) is git-ignored: it holds Dolibarr demo
data and CSRF tokens.

| Spike | Question | Status | Result / decision |
|---|---|---|---|
| Target (Dolibarr) | Can Dolibarr 23.0.4 reproduce every brief §3.3 condition, verifiable via REST? | PASS (2026-10-11) | See `dolibarr/README.md`. The payment form and the overpayment warning were exercised later, in S9. |
| S1 AI snapshot | Do `aria_snapshot(mode="ai")` refs work on Dolibarr pages? | PASS (2026-10-11) | Refs act; stale ref → `count()==0` in 7 ms; pages are 32–39k chars, so observation must be scoped. |
| S9 Payment commit | UI payment works; does Dolibarr refuse an overpayment; does a lost 504 leave exactly one payment? | PASS (2026-10-12), one caveat | `s9_payment.py`, oracle `GET /invoices/{id}/payments`. (a) One UI payment → exactly one payment. (b) Overpayment: Dolibarr shows its own warning ("payment amount … higher than the outstanding amount") with the confirm preselected to *No*, and no payment is created; answering *Yes* does create an overpayment, so this is a warning, not a hard refusal. The capability treats the warning as `validation_rejected` and never answers *Yes*. (c) `route.fetch()` then `fulfill(504)` on the confirm: server committed (302), browser showed 504, exactly one payment. The payment commit is a POST (`/compta/paiement.php`, body `action=confirm_paiement&confirm=yes`), unlike invoice validation (GET `action=confirm_valid&confirm=yes`), so commit routes match method + body. |
| S10 DB reset | Post-seed `mariadb-dump` restore < 15 s with identical REST state | PASS (2026-10-12), thin margin | `target/dolibarr/reset.sh`: dump 8.7 MB / 404 tables in 3.2 s; restore 11.9–14.4 s (≈12 s typical) on a loaded host, REST state identical (`test_reset_restores_known_state`). A plain `mariadb < dump` took 17–22 s; the restore relaxes durability for the load (global `innodb_flush_log_at_trx_commit=2`, `innodb_file_per_table=0`, `innodb_stats_persistent=0`; session unique and FK checks off; one commit), and the globals revert on db restart. Fallback if the margin bites: a volume-snapshot restore. |
| S2 Process model | One `asyncio.run()` hosts uvicorn + headed Playwright; capture across full-page posts; request log; clean Ctrl+C | PASS (2026-10-12, headed; human simulated by Playwright input) | `s2_process_model.py` via `open_session` on Dolibarr: HTTP pause holds the loop at a step boundary and resume continues it; init script + `expose_binding` capture click/change/Enter/submit across 4 full-page POST navigations with values redacted in the page; `context.on("request")` logs `action=confirm_*` GETs without the token; SIGINT (raised in-process) and task cancellation shut down cleanly with no traceback, port released and no orphan browser processes. Dolibarr list filters submit by POST. The S2 fallback (console on a thread) is not needed. |
| S6 Escape hatches | Do user-opened tabs, `file://` and DevTools escape `context.route`? | PASS (2026-10-12, headless) | `s6_escape_hatches.py`, oracle = the denied server's own hit log. A naive `context.route` lets three things escape: a WebSocket, a server 302 to a denied origin (Playwright does not route redirect hops) and a download. `new_guarded_context` contains all of them: `route.fetch(max_redirects=0)` + `Location` vetting, `route_web_socket`, downloads refused, service workers blocked. `file:`, `data:` and `chrome:` are contained. Popups, iframes, beacons, workers and form posts are contained in both variants. Manual only (a person at a headed browser): Ctrl+T tab, address bar, DevTools, drag-and-drop, Save Page As. |
| S7 Name matching | Normalized-exact matching hits "Current outstanding bill", never "… late"; handles `:`, case, NBSP | PASS (2026-10-11, offline) | `s7_name_match.py`: 9/9 probes over captured names. Rule: NFKC → NBSP→space → drop private-use icon glyphs → collapse whitespace → casefold → strip trailing `:`/`*`; anchored equality. Substring matching would have hit 2 elements for the label. Confirmation on Playwright's own name engine is a resolver test in M3. |
